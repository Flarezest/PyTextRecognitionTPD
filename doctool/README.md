# PySimpleManager: локальная проверка заявлений и паспортов РФ

> С версии 0.7.1 программа называется **PySimpleManager** (раньше — doctool). Внутренние имена не менялись: пакет и команды `python -m doctool …`, файлы `doctool_web.bat` / `doctool_gui.bat`, папка расширения `doctool_extension`, схема выгрузки `doctool.case.v1`.

Инструмент извлекает данные из заявления (PDF с текстовым слоем, DOCX, скан или фото) и из паспорта РФ (скан или фото), сверяет их между собой, выполняет формальные проверки и выносит вердикт: **принять / отклонить / ручная проверка**. Правила вердикта задаются в конфиге отдельно для каждого типа заявления.

Результат:

- HTML-отчёт с фрагментами для ручной проверки;
- выгрузка «актуальных данных» в JSON — для будущего автозаполнения во внутренней системе;
- общий Excel-реестр проверок.

Работать можно в **окне приложения**, в **браузере** (локальный веб-интерфейс) или из **командной строки**.

С версии 0.3.0 веб-интерфейс умеет сам загружать данные доменов из **manager** (Sd — администратор, S — `provider` и аккаунт) через расширение Chrome «PySimpleManager» и сверять их с паспортом и заявлением. Установка и работа — **[docs/MANAGER.md](docs/MANAGER.md)**. Домены в таблице выводятся по «проблемности»: сначала свободные по WHOIS, затем те, у которых данные в Sd не сходятся с документами, ниже — остальные (с 0.4.0). С 0.5.0 — e-mail администратора из Sd и кнопка «Выгрузка по доменам (HTML)». С 0.6.0 — статус идентификации администратора домена через Госуслуги (ЕСИА) и окно сверки Sd ↔ ЕСИА (кнопка ESIA), а также вкладка **«Смена владельца ЛК»**: базовая анкета аккаунта, сверка с заявлением и автозаполнение анкеты данными нового владельца (сохраняет оператор).

**Всё работает локально, документы никуда не отправляются.** Единственный запрос наружу — WHOIS по имени домена, которого нет в manager.

## Что проверяется

| Проверка | Как |
|---|---|
| ФИО в шапке, в «Я, …», у подписи ↔ паспорт | с учётом падежей (pymorphy3) и инициалов |
| Дата рождения, серия/номер, дата выдачи | точное совпадение; для серии/номера учитываются все варианты прочтения |
| Кем выдан | нечётко, с раскрытием сокращений (ОВД, ОУФМС, г., обл., р-на …) |
| Кем выдан (только паспорт) | надёжность прочтения + регион органа ↔ код подразделения (500-050 → Московская обл.); с данными системы — сверка с ними |
| Серия ↔ год выдачи | 3–4-я цифры серии — год изготовления бланка; опережение на 1 год — норма |
| MRZ | контрольные цифры (если зона есть, примерно с 2011 г.) |
| ИНН ИП | контрольные разряды |
| Указан прежний паспорт | номер из заявления найден в «ранее выданных паспортах» или ФИО совпадает, а паспорт старше предъявленного |
| Паспорт приложен | без паспорта заявление не принимается автоматически — «Ручная проверка» |
| Администратор доменов в manager (Sd) | ФИО и дата рождения из Sd ↔ паспорт; паспорт в Sd; домен на юрлицо; один ли администратор у всех доменов; e-mail администратора; домен не найден → WHOIS; выгрузка по доменам в HTML; ЕСИА: state и Sd ↔ данные Госуслуг (docs/MANAGER.md) |
| Смена владельца ЛК (физлицо) | базовая анкета аккаунта ↔ заявление (ввод вручную); автозаполнение базовой анкеты данными нового владельца (docs/MANAGER.md, раздел 5) |
| Домен | формат + punycode для .рф. Имя, перенесённое на следующую строку после дефиса (`business-⏎dvd.ru`), склеивается; число доменов сверяется с «всего N доменов» из заявления; обрывки имён без зоны → ручная проверка |
| Новый администратор, контакты, договор, дата заявления | заполненность; дата прописью разбирается в дату |

Адрес регистрации пока не сверяется: он стоит в штампе на страницах прописки и требует отдельного модуля.

## Установка (Windows)

1. **Python 3.10–3.13** (рекомендуется 3.12) с https://www.python.org. Старый Python можно не удалять — новый ставится рядом, запуск через `py -3.12`.
2. **Tesseract OCR** — отдельная программа (pip её не ставит): установщик `tesseract-ocr-w64-setup-5.x.exe` от UB Mannheim (https://github.com/UB-Mannheim/tesseract/wiki).
   - На шаге компонентов раскройте *Additional language data (download)* и отметьте **Russian**.
   - Проверка в новом окне командной строки: `tesseract --list-langs` — в списке должны быть `eng`, `osd`, `rus`.
   - Если `rus` нет (установщик качает языки из интернета и мог не скачать): возьмите `rus.traineddata` из https://github.com/tesseract-ocr/tessdata и положите в `C:\Program Files\Tesseract-OCR\tessdata`.
   - PySimpleManager сам ищет Tesseract в PATH и стандартных папках; если поставили в другое место — `set TESSERACT_CMD=D:\путь\tesseract.exe`.
3. Отдельное окружение и зависимости (в папке проекта):
   ```
   py -3.12 -m venv .venv
   .venv\Scripts\activate
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   pip install -r requirements-gui.txt
   ```
   Вторая строка нужна для окна и веб-интерфейса. В следующий раз достаточно `.venv\Scripts\activate` перед запуском, а `.bat`-файлы активируют окружение сами.
4. *(Необязательно, нужно для рукописных заявлений)* **Ollama** (https://ollama.com) и модель:
   ```
   ollama pull qwen3-vl:4b-instruct
   ```
   Модели нужно около 3,5 ГБ памяти. С видеокартой NVIDIA одно поле распознаётся за 1–3 с. На CPU уходит от десятков секунд до пары минут на поле.

Linux: `apt install tesseract-ocr tesseract-ocr-rus`, затем те же шаги 3–4.

## Использование

Полное руководство — интерфейсы, флаги, правила вердикта, формат выгрузки, параметры командной строки, типичные ошибки: **[docs/USAGE.md](docs/USAGE.md)**.

| Что | Как запустить |
|---|---|
| Окно приложения | `doctool_gui.bat` или `python -m doctool gui` |
| Веб-интерфейс | `doctool_web.bat` или `python -m doctool web` → http://127.0.0.1:8765 |
| Проверка из консоли | `python -m doctool check -a заявление.pdf -p паспорт.pdf` |
| Рукописное заявление | `python -m doctool --vlm qwen3-vl:4b-instruct check -a заявление.jpg --handwritten -p паспорт.pdf` |
| Поля заявления нейросетью (0.7.0) | галка «Поля заявления — нейросетью» или `python -m doctool --llm-fields qwen3:8b check -a заявление.pdf`; сравнить с шаблоном на наборах — `check_llm.bat` |
| Всё в одном файле | `python -m doctool check -a комплект.pdf --combined` |
| Пакетно | `check_all.bat` (поправьте в нём путь к папке с делами) |
| Проверить описания бланков и типов заявлений | `python -m doctool validate` (`--list` — проверки, роли полей, типы) |
| Данные доменов из manager | веб-интерфейс + расширение Chrome из папки `doctool_extension` — см. [docs/MANAGER.md](docs/MANAGER.md) |
| WHOIS домена | `python -m doctool whois example.ru` |

Каждая проверка создаёт папку `results/<дата_время>_<дело>/`:

- `report.html` — отчёт;
- `export.json` — выгрузка для системы;
- `result.json` — всё распознанное;
- `crops/` — фрагменты.

Все проверки собираются в `results/реестр_проверок.xlsx`.

### Как добавить новый бланк и тип заявления

Код менять не нужно, если новому заявлению хватает существующих проверок.

1. **Бланк.** Скопируйте `forms/regru_transfer_person.yaml` и поменяйте:
   - `id` и `detect.keywords` — фразы, по которым бланк узнаётся;
   - для каждого поля `type` — как разбирать значение (`fio`, `passport`, `domains`, `contact`… — список в шапке YAML);
   - `text` — регулярные выражения для электронного документа (группа 1 — значение). Нужны для режима без галки
     «Поля заявления — нейросетью»; бланк, который читается только нейросетью, может обойтись без них;
   - (0.7.0) `llm` — что выписать нейросети для этого поля, словами; у бланка — `llm_context` (что это за документ) и
     `llm_example` (пример ответа); `digits` — сколько цифр должно быть в значении;
   - `scan.anchor` — печатная подпись поля на бланке; `scan.region` — где относительно подписи лежит значение (`dy0/dy1` в высотах строки, `x0/x1` в долях ширины страницы);
   - для списка доменов `scan.block_start` — первая строка абзаца со списком: многострочный список на скане распознаётся ещё раз отдельно;
   - `role` — смысл поля для проверок, если имя поля другое: например, поле `owner_fio` с `role: applicant_fio` сверяется с паспортом как «ФИО в тексте». Роли — `python -m doctool validate --list`;
   - `labels_re` и `strip_prefixes` — печатные подписи в скобках и слова перед значением, которые нужно вырезать;
   - `rows` — свои строки таблицы интерфейса для полей, которых нет среди стандартных (необязательно).
2. **Тип заявления** в `config/case_types.yaml`: `form: <id бланка>`, список проверок `checks:` и правила вердикта (см. USAGE, раздел 3).
3. **Проверка:** `python -m doctool validate`. Команда находит неизвестные типы полей, роли и проверки, правила с опечаткой в названии проверки или флага, правила по проверкам, не включённым в тип, ошибки в регулярных выражениях. Тот же контроль выполняет `tests/test_config.py`.

Новая **проверка** — функция с `@register(...)` в `doctool/compare.py` (или своём модуле, подключённом в `checks._load`): в декораторе указываются id, название проверки и строка таблицы. Затем её id добавляется в `checks:` нужных типов. Таблица, «Подтверждаю», правила вердикта и отчёты подхватывают её сами.

Новый **тип значения** поля — функция с `@field_type("имя")` в `doctool/application.py`.

Отладочная картинка с найденными подписями и областями сохраняется в `results/<дело>/crops/<файл>__regions.jpg`.

## Ограничения и точность (по тестовым образцам)

- **Электронные заявления (PDF/DOCX):** поля извлекаются практически без ошибок.
- **Паспорт со сканера и MRZ:** все ключевые поля берутся из MRZ с проверкой контрольных цифр. «Кем выдан» и место рождения распознаются OCR.
- **Паспорт без MRZ или фото с телефона:** ФИО и даты обычно распознаются. Отдельные поля, например дата выдачи под печатью, могут не прочитаться и тогда помечаются для ручной проверки. При сверке учитываются все варианты прочтения серии/номера.
- **Рукописные заявления:** без VLM поля не распознаются, в отчёт попадают фрагменты для ручной сверки. С Qwen3-VL 4B цифры читаются хорошо, а в фамилиях бывают ошибки (например, «Р» читается как «Т/Г»). Поэтому всё рукописное, что не совпало с паспортом, получает статус «нужна ручная проверка», а не «расхождение».
