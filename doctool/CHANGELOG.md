# Changelog — doctool

Изменения по версиям, сверху — новые. Changelog ведётся с версии 0.2.2 (05.10.2026). Записи для 0.1–0.2.1 восстановлены по истории проекта (`claude/context/environment-and-history.md`), поэтому они менее подробны.

Как ведётся:

- Каждая версия — отдельный раздел. Внутри — «Добавлено», «Изменено», «Исправлено», «Удалено». Отдельно — «Совместимость», если меняются конфиги, формат выгрузки или поведение вердикта.
- Версия хранится в `doctool/__init__.py`. Начиная с 0.2.2 изменения патч-версии не меняют прежние вердикты на «Принять» без оснований: любое ослабление проверок отмечено в «Совместимости».
- Для сравнения с предыдущей версией в проекте лежит полный diff: `claude/changelog/doctool-{gui,cli}-<было>-to-<стало>.diff`. Актуальный код — `claude/code/doctool-gui/…` и `claude/code/doctool-cli/…`.

## [0.7.0] — 2026-10-09

Задача: новые типы заявлений без регулярок бланка. Решение пользователя:

- типовые печатные заявления по шаблону читаются регулярками, если галка «нейросеть» не стоит;
- если галка стоит — заявление читается нейросетью полностью;
- тип заявления и паспорт — регулярками, как раньше.

Перед выпуском был эксперимент 0.7.0.dev1–dev2 на наборах PhysicalPersonAdminChange set1–19 (GTX 1070,
qwen3:8b с рассуждением). Вердикты совпали с регулярками в 19 из 19, нейросеть — 46–92 с на заявление (до 184 с).
Разбор 58 отличий в полях — `claude/context/v0.7.0-dev-llm-fields.md`.

### Добавлено

- **Галка «Поля заявления — нейросетью (вместо шаблона бланка)»:**
  - веб-интерфейс и окно Qt (блок «Заявление») и поле «Модель для полей» (список моделей Ollama, по умолчанию
    `qwen3:8b`);
  - в веб-интерфейсе — подсказка, когда нужна галка;
  - поле «Локальная модель» переименовано в «Модель для рукописи».
- Командная строка:
  - `--llm-fields МОДЕЛЬ` — для `check` и `extract` то же, что галка, для `web`/`gui` — модель по умолчанию;
  - `--llm-think on|off` — рассуждение, по умолчанию `on`.
- `CaseInput.llm_fields`, `llm_model`, `llm_think`. Режим действует на одно дело (`llm_extract.session`, ContextVar):
  параллельные задачи веб-интерфейса не мешают друг другу.
- `doctool/llm_extract.py`:
  - **запрос:** правила, `llm_context`, описания полей `llm:`, `llm_example` из YAML бланка + текст заявления →
    JSON-схема (`format` Ollama), temperature 0;
  - **рассуждение:** если не уложилась в 70 % предела — повтор без него;
  - **предел** — `DOCTOOL_LLM_TIMEOUT`, 240 с;
  - **кэш ответов** — `<папка результатов>/.llm_cache`;
  - **привязка цитаты к тексту:** точно → нечётко (≥ 90) → по словам (куски, склеенные моделью). Значение — кусок
    документа. Цитаты нет в тексте → 0,55, источник `llm-…?` → «ручная проверка»;
  - **проверки ответа по типу поля:**
    - печатный текст бланка (`labels_re`, `static_text`) — не значение;
    - «ФИО» без имени, отчества или инициалов — не значение;
    - `digits:` — число цифр, у ИНН — 12;
    - «кем выдан» дополняется до границ: «выдан», дата, номер паспорта / дата, код подразделения, индекс, адрес,
      «(…)»;
    - два ФИО-поля не указывают на одно место текста (ФИО у подписи ≠ копия «Я, …»);
    - новый администратор ≠ заявитель; строка «новому Администратору: …», совпадающая с таблицей, уступает полю
      таблицы;
    - значения нового администратора — как `_usable` в регулярках;
    - домены: каждый должен быть в тексте (кроме адресов e-mail); строки списка и соседние строки с доменами
      разбираются прежним разборщиком — пропущенный нейросетью домен добавляется в список и в «прочитаны
      по-разному».
- Раздел «новому Администратору» в режиме нейросети: если на странице нового администратора не нашли, полоса раздела
  перечитывается (psm 6), и нейросеть читает только его поля.
- В бланке `regru_transfer_person.yaml`: `llm_context`, `llm_example`, `llm:` у всех полей, `digits: [12]` у ИНН.
  `validate` проверяет `llm` и `digits`.
- `llm_debug.json` в папке дела: текст для нейросети, ответ, привязка, что отброшено и почему, время, токены.
- `export.json`: `application_fields_reader` — `regex` или `llm:<модель>`. В замечаниях дела: «Поля заявления
  прочитаны нейросетью <модель> (N с)».
- `check_llm.bat` + `llm_test/` (`run_compare.py`, `compare_llm.py`, README): прогон наборов в двух режимах и сводка
  `results_cmp\llm\сравнение.html`.
- `tests/test_llm_fields.py` — 11 тестов без модели: режим на уровне дела, откат на регулярки, проверки ответа.

### Изменено

- Скан: если в тексте страницы значение оборвано посреди слова, а в области поля прочитано целиком («Виктор
  Дмитриевич Ан» / «…Андреев»), берётся область (`_region_extends`; действует в обоих режимах, на наборах set1–19
  в режиме регулярок результат не изменился).
- Бланк без регулярок (`text:`) без галки: в замечаниях — «включите „Поля заявления — нейросетью“».

### Совместимость

- Без галки поведение 0.6.0: наборы set1–19 в облаке — проверки, вердикты и выгрузка совпали с 0.6.0.
- Нейросеть недоступна (Ollama не запущена, модели нет, не уложилась) → поля читаются регулярками, в замечаниях
  дела — причина.
- Значения нейросети, найденные в тексте, получают ту же уверенность, что регулярки (0,98 / 0,85). Не найденные — 0,55
  и никогда сами не дают «Отклонить».

## [0.6.0] — 2026-10-08

Задачи: (1) статус идентификации через Госуслуги (ЕСИА) в выгрузке доменов и окно сверки Sd ↔ данные ЕСИА; (2) вкладка «Смена владельца ЛК»: базовая анкета аккаунта, сверка с заявлением (пока ввод вручную) и автозаполнение базовой анкеты данными нового владельца — только физлица.

### Добавлено

- **ЕСИА у доменов физлиц** (`ru_pp`). Расширение открывает ссылку «Идентификация через Госуслуги» со страницы Sd домена (идентификация — администратора домена, не аккаунта; у персоны ссылка `?person_id=`), берёт `state` последней по дате записи и ссылку «Смотреть файл»; файл `https://identity.reg.ru/esia/….json` загружает фоновая часть расширения (при неудаче — через фоновую вкладку). Из файла в doctool передаются только ФИО, дата рождения, гражданство, серия, номер, дата выдачи, кем выдан, `trusted`, `vrf_stu`. Страница и файл одной персоны в пределах загрузки читаются один раз. Где:
  - `content/manager.js` — `parseSd().links` (ссылки «Данные персоны услуги», «Идентификация через Госуслуги»), `parseEsiaList`, шаг ЕСИА в `lookup`;
  - `background.js` — `esiaJson`, `esiaFields`, `esiaJsonViaTab`; `manifest.json` — доступ к `https://identity.reg.ru/*`;
  - `domains.py` — `DomainInfo.esia`, `ESIA_MAP`, `esia_compare()`, `esia_summary()`; в `to_dict()` — `esia_rows`, `esia_status`, `esia_state`, `esia_ru`. Сопоставление: `person_r_surname ↔ last_name`, `person_r_name ↔ first_name`, `person_r_patronimic ↔ middle_name`, `birth_date`, `country ↔ citizenship` (RU = RUS), `passport_series ↔ rf_passport.series`, `passport_number_short ↔ rf_passport.number`, `passport_date ↔ rf_passport.issue_date`, `passport_place ↔ rf_passport.issued_by`;
  - веб-интерфейс — колонка «ЕСИА», кнопка **ESIA** рядом с Sd / S, окно сверки (зелёный — совпадает, красный — расходится, жёлтый — «кем выдан» написан по-разному);
  - выгрузка по доменам (`domain_report.py`) — колонка «ЕСИА», то же окно (данные встроены в файл), строка в «К сведению»; `report.html` — ЕСИА в колонке «Прочее».
- **Вкладка «Смена владельца ЛК»** (веб-интерфейс; вкладки «Проверка заявления и домены» / «Смена владельца ЛК»):
  - «Пользователь»: номер, «Данные пользователя #N» / «Базовая анкета пользователя #N», ссылка manager, «договор № N», логин/e-mail (через `/user/<логин>/runic_details`), домен (аккаунт — владелец услуги из S; если владелец счёта другой — замечание). В таблице доменов у номера аккаунта — кнопка «→ ЛК»;
  - данные аккаунта: базовая анкета (скрытый блок страницы `/manager/user_details`), логин, статусы (в т. ч. «Идентификация через Госуслуги пройдена»), обслуживающая организация («текущая: ООО "РДХ"»), тип анкеты (Физик / ИП / Юрик — со страницы `/user/N/runic_details`);
  - сверка «базовая анкета ↔ заявление»: фамилия, имя, отчество, дата рождения, гражданство, серия и номер, дата выдачи, кем выдан, телефон;
  - форма нового владельца и **«Заполнить автоматически»**: расширение находит или открывает вкладку «Базовая анкета пользователя #N», проверяет номер аккаунта и тип «Физик», вписывает непустые поля формы физлица (Фамилия, Имя, Отчество, Номер и серия, Дата выдачи, Кем выдан, Дата рождения, Индекс — если указан, Город — из адреса, Почтовый адрес — адрес регистрации 1 в 1, Получатель — ФИО, Телефон, Email) и вызывает события страницы (`input`/`change`/`blur`: страница помечает поля изменёнными и пересчитывает English name). «Сохранить» не нажимается. Не трогаются: Гражданство, Страна почтового адреса, Область, SMS-безопасность, Факс, English name, флажок «Внесены данные нового владельца аккаунта». Аккаунт не на физлице — вкладка открывается, заполнения нет;
  - «Кем и когда выдан документ» из заявления делится на «Кем выдан» и «Дату выдачи» (код подразделения отбрасывается);
  - «Вернуть как было» (до «Сохранить») и «Проверить, что сохранилось» (перечитать анкету и сверить).
  - Где: `doctool/account.py` (`parse_query`, `resolve_account`, `account_from_extension`, `compare_owner`, `city_from_address`, `split_issued`, `prepare_fill`, `verify_saved`; списки полей `OWNER_FIELDS`, `FILL_FIELDS`), `doctool/fieldnorm.py` (сравнение значений: текст, дата, цифры, телефон, страна, «кем выдан»), API `POST /api/owner/{parse,account,compare,prepare,fill,verify}` (`web.py`), команды расширения `account` и `fill_runic` (`background.js`: `readAccount`, `runicTab`, `fillRunic`; `content/manager.js`: `parseUserDetails`, `parseRunic`, `fillRunic`, `account`).
- Тесты: `tests/test_account.py` (8), `test_domains.py` +3 (ЕСИА), `test_extension_parsers.py` +6 (Sd → ссылка ЕСИА, страница идентификации, данные пользователя, базовая анкета, заполнение и защита от чужого аккаунта/юрлица), `test_manager_bridge.py` +1 (API вкладки). Обезличенные фикстуры: `user_details_pp.html`, `runic_pp.html`, `esia_list.html`, `esia_pp.json`.

### Изменено

- Расширение 0.6.0: страница manager распознаётся и по `nav.navbar` (новые страницы на Bootstrap, например базовая анкета, без `#content`) — в `content/manager.js` (`isManagerPage`) и `background.js` (`pageOk`). Скрипт во вкладке переинициализируется при смене версии расширения.
- `lookup` получает `task` (номер загрузки) и `esia` (по умолчанию — да); `DomainInfo.bill_owner` — логин владельца счёта.
- `check_all.bat`: папка наборов — `Dataset\PhysicalPersonAdminChange`; кроме пар `Application*` + `Passport*` проверяются папки только с паспортом («Только проверка паспорта») и только с заявлением (первый PDF/JPG/PNG).

### Совместимость

- Расширение нужно обновить (⟳ на `chrome://extensions`): новый доступ к `https://identity.reg.ru/*`. Расширение 0.5.0 с doctool 0.6.0 работает, но без ЕСИА и без вкладки «Смена владельца ЛК».
- ЕСИА на вердикт дела и группы «проблемности» не влияет.
- `export.json`: у доменов (`manager_domains`) новые поля `esia`, `bill_owner`, `esia_rows`, `esia_status`, `esia_state`, `esia_ru`.

## [0.5.0] — 2026-10-07

Задачи: (1) выгрузка по доменам из manager в HTML кнопкой; (2) e-mail администратора домена из Sd; (3) убрать проверку срока действия паспорта по возрасту и ручной ввод данных администратора; (4) ошибки распознавания на наборах 8–19 (заявления после штампа «ПОЛУЧЕНО», с потерянными подписями таблицы, в свободной форме, на бланке нотариуса, с конвертом и описью в начале файла).

### Добавлено

- **Кнопка «Выгрузка по доменам (HTML)»** (веб-интерфейс, блок «Домены в manager»). Один файл без внешних ссылок: итог по группам «проблемности», проверки, администраторы найденных доменов (паспорт/ИНН, e-mail, статусы услуг, аккаунты), «к сведению» (приостановленные/удалённые услуги, разные администраторы в одном аккаунте, один паспорт с разными «кем выдан» в Sd, не найденные домены, похожие на найденные, несуществующие зоны, «найдено несколько услуг»), таблица доменов с фильтром и ссылками на Sd/S/счета/WHOIS. Где:
  - `doctool/domain_report.py` — `build()`, `notes()`, `similar_known()`;
  - `domains.summary_checks()` — «Домены в manager» и «Администратор у доменов один» без документов (общие части вынесены в `_check_found`, `_check_same`);
  - `web.py` — `GET /api/manager/tasks/<id>/report` (загрузка кнопкой), `GET /api/jobs/<id>/domains_report` (домены дела, с проверками дела);
  - у дела с доменами файл сохраняется как `domains.html` рядом с `report.html` (`service.save_outputs`).
- **E-mail администратора домена.** Расширение передаёт `e_mail` (.RU/.РФ/.SU) и `o_email` (остальные зоны); `DomainInfo.emails` → `emails` в таблице, `report.html`, выгрузке по доменам, `export.json`. Для остальных зон — администратор из группы `o_*` (`o_company`, `o_last_name`…; `domains.intl_holder`) вместо «тип контактов не поддерживается». Группа контактов в Sd: `ru_pp`/`ru_org`, иначе `o_*` (раньше — самая многочисленная, у международного домена это пустая `a_deti_org`). Расширение — 0.5.0, обезличенная фикстура `tests/fixtures/manager/sd_intl.html`.
- **Проверка «Паспорт приложен»** (`passport_loaded`): без паспорта — «нужна ручная проверка», причина «Паспорт не загружен — сверка с паспортом не выполнялась». Раньше заявление без паспорта при заполненных полях получало «Принять».
- **Многостраничный файл заявления** (`application.extract_application`, без флажка «в одном файле»): страница бланка ищется по заголовку (`detect.title` в YAML) — перед ней бывают конверт и опись; страницы-продолжения (`detect.continuation`, нумерованный список доменов) добавляются; несколько заявлений одного заявителя — домены объединяются с замечанием; страницы паспорта в файле → подсказка отметить «Заявление и паспорт в одном файле». Быстрый OCR страниц — 1500 px, psm 3.
- **Раздел «новому Администратору» целиком** (`new_admin_block` в YAML, `application.apply_new_admin_block`, `parse_new_admin_block`): организация (ООО/АО/«Общество с ограниченной ответственностью»…, без ИНН/ОГРН), ФИО (2–4 слова, словарное имя или отчество), e-mail и телефоны — когда OCR потерял подписи «Для физ.лиц и ИП:», «ФИО», «e-mail/тел.» или заявление в свободной форме. Значения полей нового администратора без признаков юрлица/ФИО/контакта считаются обрывками подписей и убираются. Контакты «юрлица» без юрлица переносятся в контакты нового администратора. Если таблицы на странице не видно, полоса раздела распознаётся ещё раз (`_reread_new_admin`, psm 6).
- **Шапка, ФИО, паспорт в свободной форме** (`forms/regru_transfer_person.yaml`, `application.py`, `names.py`, `parsers.py`):
  - «от …» после оттиска штампа («ПОЛУЧЕ но от …»), «от гражданки Российской Федерации, …»; ФИО с переносом строки;
  - дата рождения: «, д/р 13.03.1962», «08.02.1988 гр.», «27 апреля 1988 года» (`parsers.DATE_WORDS_RE`; `parse_date` понимает месяц словом), OCR-«20.01:2018»;
  - ФИО обрезается на «прошу передать…», «года рождения», «ГР», месяце (`names.extract_fio`); порядок «Имя Отчество Фамилия» → «Фамилия Имя Отчество» (`names.ordered`, и в сравнении ФИО); фамилии на -ов/-ин не из словаря в косвенном падеже («Крайнева», «Дымовой») → именительный; род по отчеству в любом падеже;
  - «Я, …» — с отчеством на следующей строке, без «, прошу передать права…»;
  - паспорт после «Паспорт», «Серия», с «№»; дата выдачи — после «Дата выдачи:» или первая после номера (в т. ч. прописью); «Паспорт выдан: …», «Выдан: …»; из «кем выдан» убираются дата прописью, «года», «код подразделения …»;
  - номер после «ИНН», «ОГРН», «КПП» паспортом не считается (раньше ИНН нового администратора попадал в «Серию и номер»); ИНН заявителя — только из шапки;
  - адрес: «Зарегистрирован: …», «Адрес регистрации: …», «по месту жительства по адресу: …», строка с индексом над «(адрес регистрации)»;

### Исправлено

- **Имя домена, перенесённое на следующую строку, разбиралось как два куска.** В длинном списке Word переносит строку после дефиса, который входит в имя: `business-⏎dvd.ru`. Перед разбором все переводы строк заменялись пробелами (`application._clean`), получалось `business- dvd.ru`, а регулярное выражение домена находило только `dvd.ru`: кусок `business-` без зоны молча отбрасывался.

  - Число доменов при этом не менялось, поэтому ошибку не было видно.

  - строка кончается дефисом, а слева нет полного имени с зоной → имя продолжается на следующей строке, дефис остаётся (`business-⏎dvd.ru` → `business-dvd.ru`);
  - то же после склейки строк пробелом (`business- dvd.ru`): метка домена не может кончаться дефисом;
  - разрыв у точки перед зоной: `example.⏎ru`, `example⏎.ru`, `example. ru`;
  - мягкий перенос (U+00AD) из текстового слоя в имя не входит;
  - тире-разделитель (`a.ru —⏎всего…`) и полное имя слева (`a.ru-⏎…`) не склеиваются.

## [0.2.2] — 2026-10-05

Повод — тестовый образец 7 (Опря, паспорт с MRZ, режим «Только проверка паспорта»). В 0.2.1 он давал «Принять», хотя дата выдачи была отброшена, а «кем выдан» не проверялся.

### Добавлено

- **Модуль `doctool/issuer.py`:**
  - таблица субъектов РФ по коду подразделения; коды бывших АО переведены в нынешние субъекты (81 → 59 и т. д.);

  - проверка, что текст похож на название органа.
- **Проверка «Кем выдан» в режиме `passport_only`** (`compare.issuer_reading_check`). Смотрит, распознано ли поле, похоже ли оно на название органа (МВД/ОВД/УФМС/отдел…) и надёжен ли источник. Модель или OCR с уверенностью < 0,6 → «нужна ручная проверка».

- **Проверка «Кем выдан ↔ данные системы».** Работает, если в данных администратора заполнено `passport_issued_by` и в системе тот же паспорт.
- **`AdminData.passport_issued_by`.** Поле «Кем выдан» добавлено в данные администратора в окне Qt и веб-интерфейсе. В `export.json` → `system_update` появилось `passport_issued_by` («было → станет»).

- **Тестовый образец** `Dataset\set7\PassportSet7.png` (Опря).

### Изменено

- **`passport_rf._merge_lines`.** Строка из нескольких проходов OCR выбирается по согласию проходов, а не по максимуму «уверенность × длина». Для «кем выдан» приоритет получают слова названий органов («ОБЛАСТИ», а не «ВЛАСТИ»).
- **«Кем выдан» из OCR.** Явные опечатки правятся: «РООСИИ» → «РОССИИ», «МОСКОВСКОЙ ВЛАСТИ» → «… ОБЛАСТИ». Исходное прочтение сохраняется в `alternatives` и `raw`, список правок — в `debug.issued_by_fixes`.
- **Проверка «Серия ↔ год выдачи».** Если год бланка по серии опережает год выдачи на 1 год, это «к сведению» (бланки печатают с опережением). На 2–3 года → «проверить». Больше 3 лет → «так не бывает».

  - значения из MRZ и введённые оператором не отбрасываются никогда;
