# Данные доменов из manager (расширение Chrome)

С версии 0.3.0 doctool умеет сам получать из manager данные доменов из заявления:

- **Sd** — администратор домена;
- **S** — поле `provider` (текущий регистратор) и номер аккаунта.

Дальше эти данные сверяются с паспортом и заявлением. Работает только в **веб-интерфейсе** (`doctool_web.bat`).

Данные из manager читает расширение Chrome «doctool — manager». Оно работает в вашем Chrome, от вашего входа в manager, и делает то же, что вы делаете руками:

1. ищет домен в поле «Позиция»;
2. открывает Sd;
3. открывает S.

Расширение ничего не нажимает и ничего не меняет в manager.

---

## 1. Установка (один раз)

1. **Обновите зависимости.** В 0.3.0 добавился пакет `websockets`. В папке программы выполните:

   ```
   py -3.12 -m pip install -r requirements.txt -r requirements-gui.txt
   ```

2. **Установите расширение в Chrome:**
   1. Откройте адрес `chrome://extensions`.
   2. Справа вверху включите **«Режим разработчика»**.
   3. Нажмите **«Загрузить распакованное расширение»** и выберите папку `doctool_extension` из архива программы.
   4. Появится карточка «doctool — manager 0.5.0». Нажмите на значок-пазл на панели Chrome и закрепите значок расширения (синий квадрат с буквой «d»).

   Не удаляйте и не перемещайте папку `doctool_extension`: Chrome загружает расширение прямо из неё. Если папку переместили, удалите расширение и загрузите его заново из нового места.

3. **Запустите doctool:** `doctool_web.bat`. Через несколько секунд:
   - в шапке веб-интерфейса появится зелёная точка и надпись «manager: расширение подключено»;
   - на значке расширения пропадёт красный «!».

4. **Войдите в manager в этом же Chrome**, как обычно.

После обновления файлов расширения откройте `chrome://extensions` и нажмите ⟳ на карточке «doctool — manager».

---

## 2. Как пользоваться

### Автоматически, вместе с проверкой заявления

1. Отметьте флажок **«Подгрузить данные Sd доменов из заявления автоматически»**. Он запоминается.
2. Загрузите заявление и паспорт и нажмите **«Проверить»**.
3. После сверки заявления и паспорта в «Ходе работы» появятся строки `manager [1/N]: домен…`.
4. В результате появится таблица **«Домены в manager»**. Вердикт учтёт данные доменов.

### Вручную, кнопкой

В блоке **«Домены в manager»** впишите домены через пробел, запятую или с новой строки и нажмите **«Загрузить данные из manager»**. После проверки заявления домены из него подставятся в это поле сами.

- **Проверка заявления уже выполнена:** данные доменов добавятся к этому делу, вердикт, отчёт и `export.json` пересчитаются.
- **Проверки ещё не было:** просто покажется таблица доменов, без сверки с документами.

## 3. Что показывается

| | Физлицо (ru_pp) | Юрлицо (ru_org) |
|---|---|---|
| Из Sd | ФИО, дата рождения, серия и номер паспорта, дата выдачи, кем выдан, страна, дата последней смены администратора (`last_admin_change`), e-mail (`e_mail`) | название организации (`org_r`), ИНН (`code`), страна, дата последней смены администратора, e-mail (`e_mail`) |
| Из S | `provider` — текущий регистратор, `user_id` — аккаунт, в котором лежит домен | то же |

Ещё в таблице:

- статус услуги из Sd («Активна (A)»);
- ссылки **Sd** и **S**: открывают эти страницы manager в новой вкладке.

Если поля `last_admin_change` в Sd нет, в таблице стоит «—».

**Домен не найден в manager.** В таблице стоит «не найден», и doctool делает **WHOIS-запрос**: свободен ли домен, у какого регистратора и до какой даты оплачен. Если WHOIS недоступен (в сети закрыт порт 43), рядом будет ссылка для ручной проверки.

**Порядок строк — по «проблемности»** (с 0.4.0). Домены разбиты на группы, у каждой — заголовок с числом доменов:

| Группа | Когда |
|---|---|
| Свободен по WHOIS | в manager не найден, WHOIS: домена нет в реестре |
| Данные в Sd не сходятся с документами | в Sd другое ФИО, дата рождения, паспорт другого человека или другой ИНН |
| Нет в manager | в manager не найден, WHOIS: занят у другого регистратора или WHOIS не проверялся |
| Данные из manager не получены | ошибка, таймаут, нет входа в manager, загрузка остановлена |
| Нужна ручная сверка | домен на юрлицо, неуверенное сходство ФИО, неизвестный тип контактов |
| Мелкие расхождения | тот же паспорт, но другая дата выдачи или «кем выдан» |
| К сведению | например, в Sd прежний паспорт, подключён Trustee |
| Найден, сверка не выполнялась | данные загружены кнопкой до проверки дела |
| В порядке | всё совпало |

Внутри группы домены идут в порядке заявления. Тот же порядок — в разделе «Домены в manager» файла `report.html`. В `export.json` (`manager_domains`) порядок — как в заявлении, у каждого домена есть поля `problem` (код группы), `problem_ru` и `problem_rank`. В комментарии проверки «Домены в manager» свободные домены тоже перечисляются первыми. Группы задаются в `doctool/domains.py` (`PROBLEMS`).

---

**E-mail администратора** (с 0.5.0). В таблице и в отчётах под ФИО/названием администратора: для .RU/.РФ/.SU — поле `e_mail` из Sd, для остальных зон — `o_email`. Если адресов несколько (по строке на адрес), показываются все.

**Остальные зоны** (.com, .москва и т. п.). Администратор (владелец) — группа `o_*` в Sd (`o_deti_org`, `o_gtld`…): показываются организация (`o_company`) или ФИО, страна (`o_country_code`) и e-mail. Автоматической сверки с паспортом для них нет — «нужна ручная проверка».

### Выгрузка по доменам (HTML)

Кнопка **«Выгрузка по доменам (HTML)»** в блоке «Домены в manager» (активна, когда таблица заполнена). Скачивается один HTML-файл без внешних ссылок — его можно переслать:

- итог по группам «проблемности» (со ссылками на группы);
- проверки: если домены загружены после проверки дела — проверки дела по доменам (в т. ч. сверка Sd с заявлением и паспортом); если без дела — «Домены в manager» и «Администратор у доменов один»;
- администраторы найденных доменов: ФИО/организация, паспорт или ИНН, e-mail, статусы услуг, аккаунты, число доменов;
- «к сведению»: статусы услуг (приостановлена, удалена), разные администраторы в одном аккаунте, один и тот же паспорт с разными «кем выдан»/датой выдачи в Sd, не найденные домены, похожие на найденные (вероятная ошибка распознавания: `vstshakii.ru → vst-shakti.ru`), несуществующие зоны, «найдено несколько услуг»;
- таблица доменов с фильтром (домен, ФИО, паспорт, ИНН, e-mail), ссылками на Sd/S/счета и WHOIS.

Для дела файл также сохраняется в его папку — `domains.html` рядом с `report.html`.

**Несуществующая зона** (с 0.5.0). Если зоны нет в корневой зоне IANA (например, «chi.pd» — ошибка распознавания «.рф»), WHOIS даёт «ошибка: зоны .pd не существует», а не «свободен».

## 4. Как сверяется и как влияет на вердикт

| Проверка | Как | Итог |
|---|---|---|
| **Домены в manager** | все домены из списка найдены? | не найден → «расхождение» → «Ручная проверка» (причина: «Домен из заявления не найден в manager») |
| **Заявитель — администратор доменов (Sd)** | ФИО и дата рождения в Sd ↔ паспорт (если паспорта нет — заявление) | совпали → «в порядке»; другое лицо → «расхождение» → **«Отклонить»** («Заявитель не является текущим администратором домена»); похоже, но не точно или домен на юрлицо → «нужна ручная проверка» |
| **Паспорт в Sd** | серия и номер; если паспорт тот же — ещё дата выдачи и «кем выдан» | другой номер при совпадающих ФИО и дате рождения → «к сведению» (в Sd старый паспорт, его нужно обновить); тот же паспорт, но другая дата или «кем выдан» → «проверить» |
| **Администратор у доменов один** | у всех найденных доменов один администратор (по паспорту / ИНН) | разные → «проверить» |

Латиница из Sd (`person_surname` и т. п.) не сверяется: в manager встречаются разные варианты транслитерации.

## 5. Вход в manager

Если manager показывает окно **«Войти»**, расширение:

1. выводит вкладку manager на передний план;
2. пишет в «Ходе работы»: *manager просит вход…*;
3. ждёт, пока вы войдёте (по умолчанию до 3 минут), и продолжает само.

Если окна «Войти» не видно, обновите вкладку manager (F5).

Если за отведённое время вход не выполнен, домен получает ошибку «Вход в manager не выполнен», остальные домены пропускаются. Войдите и нажмите «Загрузить данные из manager» ещё раз.

Проверить вход заранее: значок расширения → **«Проверить вход в manager»**.

## 6. Что делает расширение и что уходит наружу

- **Своя фоновая вкладка.** Расширение открывает вкладку `https://manager.reg.ru/` в фоне и загружает в ней страницы:
  - `/bill/bills?searchstring=<домен>&from_head=1&_csrf=<токен>`;
  - `/tech/srv_details?service_id=…`;
  - `/tech/service_details?service_id=…`.

  Это обычные GET-запросы — то же самое, что переход по ссылкам. Вкладка закрывается через 60 секунд без работы. Ту вкладку, которую вы сейчас смотрите, расширение не закрывает.
- **Только чтение.** Кнопки «Изменить», «Удалить», «Совершить массовое действие» и формы manager расширение не трогает.
- **В doctool передаются только перечисленные выше поля.** С 0.5.0 к ним добавлен контактный e-mail администратора: `e_mail` (.RU/.РФ/.SU) и `o_email` (остальные зоны), а для остальных зон — название организации или ФИО владельца (`o_company`, `o_last_name`… группы `o_*`). Код передачи домена (`authinfo`), телефоны, адреса, `FOA_token` и служебные поля из manager не забираются.
- **Связь только внутри компьютера.** Расширение связывается только с doctool на этом же компьютере (`ws://127.0.0.1:8765/ext`). doctool принимает подключения только от расширений Chrome, обычные сайты подключиться не могут.
- **WHOIS — единственный запрос наружу.** Только для доменов, которых нет в manager, и в нём уходит только имя домена:
  - .RU / .SU / .РФ → `whois.tcinet.ru:43`;
  - другие зоны → WHOIS их реестра или `rdap.org`.

Проверить WHOIS из командной строки: `py -3.12 -m doctool whois example.ru`.

## 7. Настройки расширения

Правой кнопкой по значку расширения → **«Параметры»**:

| Настройка | По умолчанию | Зачем |
|---|---|---|
| Порт doctool | 8765 | если запускаете `doctool web --port …` |
| Сколько ждать входа в manager | 180 с | время на ввод логина и пароля |
| Пауза между доменами | 300 мс | чтобы не нагружать manager при длинных списках |
| Закрывать вкладку manager через | 60 с | 0 — не закрывать |

## 8. Если что-то не так

| Что видно | Что сделать |
|---|---|
| «manager: расширение не подключено» | Проверьте по порядку:<br>• Chrome запущен;<br>• расширение включено в `chrome://extensions`;<br>• doctool запущен на порту из настроек.<br>Затем значок расширения → «Переподключиться». |
| Красный «!» на значке расширения | doctool не запущен или порт другой. |
| «Вход в manager не выполнен» | Войдите в manager в этом Chrome и повторите. |
| Домен «не найден», хотя он есть в manager | Найдите его вручную в поле «Позиция» и посмотрите, как он записан в колонке «Название». Сохраните страницу (Ctrl+S) и пришлите — поправим поиск. Особенно это касается доменов .РФ: на реальных страницах они ещё не проверялись. |
| «По домену найдено несколько услуг» | У домена несколько активных услуг — разберитесь вручную по ссылкам. |
| «WHOIS недоступен … порт 43» | В сети закрыт WHOIS. Проверьте по ссылке «проверить WHOIS вручную». |
| Chrome при запуске предлагает отключить расширения в режиме разработчика | Нажмите «Отмена». Если режим разработчика запрещён политикой компании — нужен администратор, чтобы установить расширение централизованно. |

## 9. Ограничения

- **Только веб-интерфейс.** В окне Qt загрузки из manager нет.
- **Поиск в счетах — по первой странице выдачи** (25 позиций). Для доменов с очень длинной историей счетов строка домена может не попасть на первую страницу.
- **Типы контактов:** `ru_pp` и `ru_org` сверяются с документами. Остальные (группы `o_*` других зон) — показываются администратор и e-mail, сверка — вручную.
- **Домен на юрлицо** со сверкой бланка физлица — всегда ручная проверка.
- **Автозаполнения форм manager пока нет.** Это следующий этап («Перенос доменов между аккаунтами»).
